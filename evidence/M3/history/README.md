# Retained development timing failure

The pre-final USB qualification used an unconditional five-tick lateness ceiling in normal multi-thread TCG. One case failed after its functional workload completed. The original [report](deadline-before-fix-results.json) and [USB log](deadline-before-fix-usb.log) are retained. A subsequent [repeated USB run](deadline-repeat-17-ticks.log) measured 17 ticks maximum lateness while the same functional assertions completed; other repeated runs observed zero.

No definitive attribution between host scheduling, TCG translation and guest contention is established by that log alone. The final qualification separates these claims: HPET monotonicity/no-early-wake and termination are mandatory everywhere; raw SMP lateness remains reported, without a hard real-time claim. An additional single-CPU instruction-counted QEMU run checks the five-tick lateness budget under a controlled virtual clock. It does not replace actual 2/4-CPU native/concurrent runs. Kernel clock regression/catch-up, resource and functional failures remain fatal to acceptance. Cross-CPU completion uses join notifications rather than fixed test delays, and thread records are checked for complete reaping.

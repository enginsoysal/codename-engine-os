# M4.5 evidence — in progress

These are increment reports, not full M4.5 completion. [Owner trust policy and external qualification prerequisites](../../docs/milestones/m4.5-owner-trust.md) remain explicit. [Agreed acceptance](../../docs/milestones/m4.5.md), [implemented increment/limits](../../docs/milestones/m4.5-storage.md).

[Increment qualification](increment-results.json), [source/artifact manifest](build-manifest.json). The full milestone flag deliberately remains false.

- [SMP pressure correction](../../docs/milestones/m4.5-smp-pressure.md): exact pre-fix reproduction, short-delay recovery, deadline negative and eight restricted-host-CPU repeats. Current M3 regressions qualify the shared scheduler change.
- [Dual-firmware boot matrix](boot/results.json): the same ISO and USB images boot through pinned OVMF and SeaBIOS; native completion, actual framebuffer captures and per-CPU HLT observations. [BIOS boundary tests](boot/negative-results.json) cover medium geometry, CRC, insufficient memory, graphics dimensions and serial fallback.
- [VMware matrix](vmware/results.json): EFI/BIOS SATA and IDE plus EFI/NVMe on Workstation 26.0.1; native completion and ordinary first-sector reads at two CPUs/128 MiB. Existing running VM inventory and full backing hashes remain unchanged. This does not qualify VMware USB/input or every storage error path.
- [Storage/partition report](storage-results.json): real AHCI/NVMe/ATA/VirtIO reads, ordinary capacities, 512/4096-byte sectors, primary/backup GPT and MBR validation, NTFS/exFAT recognition, corruption rejection, NVMe/VirtIO queue wrap and mixed-disk selection/write isolation. Ordinary backing files are independently hashed before/after.
- [FAT32 report](fat32-results.json): real native AHCI/NVMe reads of short-name and UTF-16 long-name files, malformed LFN checksum rejection and unchanged backing files.
- [USB lifetime/input/fault report](usb/results.json): real BOT/FAT32 reads, repeated root-port reconnect, retired disk references, keyboard reconnect, mouse reports, exact DMA reclamation, a read-EIO device and healthy replacement, four-CPU HLT and a measured host idle interval.
- [USB timeout report](usb-timeout/results.json): a real throttled pending read reaches the native timeout; DMA pages stay retained until safe disable, are reclaimed afterward, and a healthy replacement reads successfully. Input and four-CPU idle remain functional.
- [Rejected root interface](usb-reject/root/results.json) and [hub interface](usb-reject/hub/results.json): a rejected final port leaves no input ring on a freed context; healthy keyboard input and CPU idle remain functional.
- [Hub topology](hubs/direct/results.json) and [five-hub chain](hubs/nested/results.json): actual storage and HID input, repeated leaf reconnect, entire populated-tree removal/rebuild and exact DMA lifetime.
- UAS [high-speed EIO](uas/hs-eio/results.json), [SuperSpeed EIO](uas/ss-eio/results.json), [high-speed deadline](uas/hs-timeout/results.json) and [SuperSpeed deadline](uas/ss-timeout/results.json): native reads, real stream contexts, bounded task abort, healthy replacement, backing hashes and measured CPU/page accounting.
- [Extended ext2 report](ext2/results.json): native 1/2/4-KiB blocks, 128/256/512-byte inodes, two groups, indirect reads, sparse data, UTF-8 paths, temporary-buffer reclamation and damaged metadata rejection. Fixtures do not carry an external e2fsck qualification.
- [Read-EIO report](faults/results.json): actual failing AHCI/NVMe/VirtIO transfers remain visible as unreadable disks. USB EIO runs after firmware boot in the USB report.
- [SHA-256 report](sha256-results.json): exact original C implementation compared with independent known/boundary digests.
- [Secure Boot report](secure-boot-results.json): owner-enrolled disposable TCG firmware policy; genuine SecureBoot/SetupMode readback, valid signed loader, unsigned/tampered loader rejection, tampered external kernel/init rejection. The suite also covers persistent encrypted signing, payload update continuity, temporary-key cleanup, authenticated db rotation, authority separation, retired/foreign signer rejection, replay refusal and explicit VM policy-snapshot recovery. The private test key/enrollment media are not published.

Every runtime report has its own tested build identity or source/provenance hashes. Native drivers are tested after firmware handoff; host-only parsers or a boot screen are not substituted for transfers. Physical hardware, factory trust, production owner-key qualification and broader unsupported controller/USB profiles remain open.

Development observations: SATA signatures initially remained unknown until our driver enabled receive FIS and initialized the link. The driver now owns that step. The pinned QEMU ATA model refuses 4096-byte logical sectors; NVMe supplies that test profile. OVMF repaired a primary-only GPT corruption before kernel entry, so the negative fixture now damages both copies. Newer firmware required proof-of-possession for initial PK enrollment; the test helper now uses a signed authenticated-variable update. These are resolved development observations, not hidden passing tests.

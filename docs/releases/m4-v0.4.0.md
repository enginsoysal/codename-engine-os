# M4 v0.4.0 — persistent filesystem and input

Original AHCI initialization, one outstanding MSI-completed request with CPU HLT waits and 4 KiB DMA batches; bounded writable ext2/VFS; an original xHCI driver for directly attached USB boot keyboard/mouse; PS/2/COM1 fallback and an interactive diagnostic file console.

The native filesystem probes cover create/read/modify/rename/unlink across reboot, 48 KiB files, case/UTF-8 preservation, generation/quota/share handles and blocked rename/delete while open. Independent host checking validates graph, block ownership, maps/counts and file data. Failure tests cover full disk, rejected media, write errors after a durable dirty marker, timeout/DMA quarantine and recovery to a new copy. There is no journal or universal power-loss recovery guarantee.

Named qualification includes pinned QEMU q35/OVMF ISO/USB, 64 MiB/one CPU and 128 MiB/two or four CPUs, actual USB/PS/2 key events, mouse motion/buttons, idle HLT/resource measurements and two VMware Workstation 26.0.1 SATA persistence boots. The earlier M3 suite is rerun separately. See [acceptance/evidence](../../evidence/M4/README.md), [development failures/fixes](../../evidence/M4/development-notes.md) and [exact contracts](../milestones/m4-contract.md).

Assets: bootable ISO, USB image, kernel/user ELF, map, source/artifact manifest, checksums and the filesystem-template IMG/VMDK pair. Copy both template files together into a disposable VMware directory before attaching the VMDK as SATA. Old alpha version-1 data images are intentionally rejected and must be preserved. No disk is needed to view the console, but persistence needs the marked version-2 disk.

M4 completion is within this bounded native virtual-device profile. Physical controllers, hubs/hotplug, arbitrary HID, large/indirect files, links/ACLs, untrusted file syscalls and guest compatibility remain outside it. M5 brings the installer/live/install/recovery workflow; this release has no installer, desktop or existing Windows application support.

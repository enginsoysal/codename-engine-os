# Engine OS 0.7.2 — install, open your desktop, explore your folders

This release focuses on a redesigned native installation wizard and a real persistent folder desktop. After verified installation, **Open desktop** enters Files immediately. Back/Forward/Up, a places sidebar, named folders, paging, protected system browsing and the existing window/taskbar model support exploring your installed workspace. Optional application expansion and Windows compatibility are deferred.

[VMware starter ZIP](https://github.com/enginsoysal/codename-engine-os/releases/download/m72-v0.7.2/EngineOS-M72-VMware.zip) · [Standalone ISO](https://github.com/enginsoysal/codename-engine-os/releases/download/m72-v0.7.2/EngineOS-M72.iso) · [Installation tutorial](../handbook/install-m72.md) · [Desktop guide](../handbook/desktop-m72.md) · [Acceptance](../../evidence/M7.2/acceptance-results.json).

The ZIP contains a **new blank** growable 20-GiB SATA disk, relative-path VMware configuration and matching ISO. Extract it all, open EngineOS.vmx, start, follow Next and install. Choose Open desktop at the end. No network or terminal is required. For later independent boot, disconnect only CD/DVD and keep the SATA disk connected. Existing installs can use Recovery/Update; installation over an existing disk erases the whole disk only after separate review consent.

## Scope

M72-VM-v1 uses original native x86-64 Engine OS on named QEMU and VMware BIOS/UEFI profiles, unsigned/Secure Boot off and SATA/AHCI 512-byte sectors. The first immediate desktop uses the installation kernel against persistent installed storage. Separate tests boot the same VMware VM with its NVRAM and disconnected optical media twice without a boot-order override. The exact public starter ZIP is tested, including its new disk. Networking is unnecessary for the two priority tasks.

The user's firmware No Media cause remains unproven; no universal hardware or firmware fix is claimed. Other installation transports, selected-partition OS installation, partition resize/move, automatically mounted foreign volumes and arbitrary desktop components remain outside scope. Personal/system UI protection is not a multiuser ACL. DOS and Windows 1.x–11 applications remain M8. Earlier release assets/evidence are retained unchanged.

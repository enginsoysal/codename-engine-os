## Delivered behavior

Phase 1 supplies a bounded common inventory and actual provider capabilities in
Settings → Devices and advanced hardware reporting. Ready, Limited, Detected and
Unavailable do not confuse PCI recognition with an available device function.
Supported storage, display, input and Ethernet providers bind automatically.
No separate guest driver installer or manufacturer control suite is required.

Phase 2 adds saved US QWERTY/Dvorak selection, real focused Files wheel input,
qualified USB HID/hub/reconnect behavior and native removable FAT32 file tasks.
Browse USB drives, copy selected files to Downloads, use To USB for the reverse
copy, flush, safely remove and reconnect. Existing destinations are never
silently overwritten. Boot streaming removes a temporary full-kernel ELF copy.
[Design choices and limits](../architecture/hardware-m10.md),
[native usability review](../architecture/usability-review-m10.md).

## Known limits

- **64-MiB OVMF with USB storage attached before firmware boot remains unqualified.**
  The original MSI init bundle can lack a suitable contiguous allocation. The
  successful 64-MiB journey connects storage after installed startup. The ordinary
  VMware package uses 128 MiB. This failure is preserved separately with
  `passed: false`, never counted as a successful gate.
- The write profile is supported BOT media with 512-byte sectors, working flush,
  a clean mirrored FAT32 volume and a supported first volume. UAS stays read only.
  Each copy is one file up to 64 MiB, with bounded contiguous allocation and free
  directory slots. ASCII export names are at most 63 bytes; GUI import names 55.
  No directory growth, overwrite, deletion, repair or power-loss atomicity is supplied
  by this broker. Failed writes may require an offline FAT check.
- Transfers display a keep-connected message and run synchronously; mid-copy
  cancellation, exFAT/NTFS writing, USB OS installation and USB formatting remain
  outside this slice. Eight USB devices and one xHCI controller are bounded limits.
- US QWERTY/Dvorak and proven HID layouts do not mean all international input
  methods or arbitrary HID descriptors. Runtime monitor changes, multiple displays,
  physical/ARM qualification and vendor GPU 3D are not delivered here.
- Broader Ethernet/Wi-Fi, comprehensive audio, vendor acceleration, Windows Steam
  games and laptop/other device families remain later hardware phases. General
  Windows GUI/MSI, DOS and Windows 1.x–11 compatibility remain separate work.
  Historical unqualified QEMU SAS/PVSCSI cases remain unqualified.

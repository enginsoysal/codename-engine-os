# M4.5 v0.4.5 — final VM-scoped milestone

M4.5 is complete within the user-approved **M45-VM-v1** contract. This is the final milestone checkpoint and an OS development release, not a production desktop OS. [Acceptance](../../evidence/M4.5/acceptance-results.json), [scope](../milestones/m4.5.md), [contract](../milestones/m4.5-scope.json).

## Download and verify

[GitHub release](https://github.com/enginsoysal/engacer-os/releases/tag/m45-v0.4.5). Download `EngineOS-M45.iso` for VMware. `EngineOS-M45-usb.img` is the raw USB boot image; kernel ELF/map, native user ELF, build manifest and `M45-SHA256SUMS.txt` complete the seven public assets. Private keys, firmware-variable files and enrollment/negative-test media are excluded.

Compare the ISO against `M45-SHA256SUMS.txt` and the artifact hash in `m45-build-manifest.json`:

```powershell
Get-FileHash .\EngineOS-M45.iso -Algorithm SHA256
```

## VMware setup

1. Use a separate x86-64 VM. The tested guest profile is **FreeBSD 64-bit**, with virtual hardware version 20. That setting selects virtual hardware; Engine OS runs its own kernel.
2. Set **2 vCPUs and 128 MiB RAM** to reproduce the named Workstation 26.0.1 build 25688693 profiles. Configured VM RAM is not the OS's managed memory consumption.
3. Select **UEFI with Secure Boot disabled**. Legacy BIOS is also qualified using the same ISO. The public image is unsigned; enabled-Secure-Boot tests use separate owner-signed QEMU media.
4. Attach the ISO to the virtual CD/DVD drive and enable **Connect at power on**. Boot the CD/DVD first. Disable 3D acceleration, network and the USB controller to reproduce the VMware matrix; PS/2 is the diagnostic input route. Detailed USB/input tests use QEMU xHCI.
5. A disk is optional for boot. For storage inspection, attach a separate disposable SATA, IDE or NVMe virtual disk. EFI/BIOS SATA and IDE plus EFI NVMe are qualified. Existing operating-system disks are unnecessary.
6. Power on. Expect **CODENAME: ENGINE OS**, **M4.5 DEVICE AND FILE CONSOLE**, then `engine>`. Enter `help`, `info`, `hardware` or `disks`.

**SCSI controllers are not supported in M4.5**, including LSI Logic/LSI SAS, BusLogic and VMware Paravirtual SCSI. A FreeBSD guest preset can select SCSI automatically. If `disks` has no entries, partitioning is not the remedy: use a supported controller first. [Step-by-step 20-GB SATA setup and troubleshooting](../handbook/vmware-storage.md).

A blank/unformatted disk or no writable development filesystem is a valid state. Ordinary disks are inspected read-only; files require a supported FAT32/ext2 filesystem. There is no installer, partition formatter or desktop yet. The marked M4 development volume is a separate test-only writable profile.

If VMware opens its firmware menu, confirm that CD/DVD is connected and select the optical boot entry. Both EFI and BIOS can boot this ISO; it is not necessary to install FreeBSD. Keep Secure Boot disabled for the public download. Record the build ID and exact message if native boot fails. No claim is made for every VMware version/device configuration.

## Qualification and remaining work

`python tests/m45/verify.py` executes 29 gates: dual-firmware ISO/USB, early boot negatives, storage/partitions/filesystems, driver binding/input, hub/UAS reconnect and fault/deadline containment, resource/HLT/SMP checks, 23 owner-trust checks, five VMware profiles and M4/M3/M0 regressions. VMware records the SHA-256 of the exact final ISO; normal and failure-path tests require real native behavior. Source/artifact/evidence hashes identify the qualified files.

Physical hardware, factory-trusted Secure Boot and production key operations are separate unqualified tracks, not blockers for this agreed VM milestone. ARM64/Raspberry Pi is M16. Windows 95–11 application compatibility remains a long-term target; no existing Windows app support is supplied by this release. M5 installation is next and has not started.

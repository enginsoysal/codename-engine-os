# M7 — real Engine OS desktop

Status: **in progress**, started 7 November 2026. M6 v0.6.0 and its accepted artifacts remain unchanged. The product remains Engine OS. [Owner contract](../roadmap/milestones.md).

## Delivery order

1. Implement bounded window ownership, stacking, focus, move/resize/minimize/close, invalidation and a native desktop session. Connect the M6 installer to installed desktop boot using separately named M7 media.
2. Add native editor, file manager, Settings, launcher and independently removable Calculator. Save actual documents and preferences to the installed volume. Provide clipboard and keyboard routes alongside mouse interaction.
3. Establish checked application/service boundaries, private state, quotas and contained failure. A kernel callback with a decorative window is not an isolated application.
4. Implement supported networking, automatic configuration, DNS, valid clock/certificate checks and actual HTTPS file downloads. Verify bytes and handle certificate rejection, disconnection and recovery.
5. Qualify real installed desktop tasks, restart persistence, removal/crash containment, custom distribution choices, damage-driven painting and memory-pressure/idle behavior. Publish exact firmware/device/CPU/RAM limits, English handbooks, a GitHub release and a VMware ISO.

## Initial architectural choice

Use a small original window model independent of renderer and apps. Eight windows and generation-bound identities give a concrete resource bound; stale identities cannot manipulate reused windows. A bounded union of invalidated rectangles permits repainting changed regions without a permanent refresh loop. Clamp hostile geometry in widened arithmetic and keep the launcher/taskbar reachable after moves or resizing.

This choice avoids a full-screen backing allocation per window. The renderer can repaint the visible intersecting windows into damaged screen regions in stacking order. CPU rendering is the initial path; hardware acceleration remains a separately measured extension. Rendering and application state must not be coupled to optional Calculator code.

The first window-model checks are host tests of real C, not desktop runtime qualification. M7 remains incomplete until the native installed session and the networking/security/user-task gates pass. Existing storage limits remain explicit and must be extended if a qualified desktop task requires more capacity or entries.

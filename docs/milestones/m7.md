# M7 — real Engine OS desktop

Status: **in progress**, started 7 November 2026. M6 v0.6.0 and its accepted artifacts remain unchanged. The product remains Engine OS. [Owner contract](../roadmap/milestones.md).

## Delivery order

1. Implement bounded window ownership, stacking, focus, move/resize/minimize/close, invalidation and a native desktop session. Connect the M6 installer to installed desktop boot using separately named M7 media.
2. Add native editor, file manager, Settings, launcher and independently removable Calculator. Save actual documents and preferences to the installed volume. Provide clipboard and keyboard routes alongside mouse interaction.
3. Establish checked application/service boundaries, private state, quotas and contained failure. A kernel callback with a decorative window is not an isolated application.
4. Implement supported networking, automatic configuration, DNS, valid clock/certificate checks and actual HTTPS file downloads. Verify bytes and handle certificate rejection, disconnection and recovery.
5. Qualify real installed desktop tasks, restart persistence, removal/crash containment, custom distribution choices, damage-driven painting and memory-pressure/idle behavior. Publish exact firmware/device/CPU/RAM limits, English handbooks, a GitHub release and a VMware ISO.

## Initial architectural choice

Use a small original window model independent of renderer and apps. Eight windows and generation-bound identities give a concrete resource bound; stale identities cannot manipulate reused windows. A bounded union of invalidated rectangles permits repainting changed regions without a permanent refresh loop. Clamp hostile geometry in widened arithmetic and keep the launcher/taskbar reachable after moves or resizing.

This choice avoids a full-screen backing allocation per window. The renderer can repaint the visible intersecting windows into damaged screen regions in stacking order. CPU rendering is the initial path; hardware acceleration remains a separately measured extension. Rendering and application state must not be coupled to optional Calculator code.

The first window-model checks are host tests of real C, not desktop runtime qualification. M7 remains incomplete until the native installed session and the networking/security/user-task gates pass. Existing storage limits remain explicit and must be extended if a qualified desktop task requires more capacity or entries.

## Historical first native desktop slice

A separately named `EngineOS-M7.iso` development build reuses the installed M6 layout and verified-bundle installation mechanism. Installed boot enters a real native framebuffer desktop with a launcher, stacking/focus, movable/resizable/minimizable windows, Files, a bounded text editor, clipboard actions, preferences and integer Calculator. The editor saves to the actual native volume; the development VM test independently checks GPT/metadata/payload checksums and exact text after detached restart.

That first slice used trusted kernel UI callbacks and only disabled Calculator. It did not satisfy application isolation, executable component removal or networking/HTTPS. Its images remain as development history. The editor has an explicit 8,191-byte bound. The generic M5.1 launcher does not run this image. Build with `python tools/build/m7.py` and exercise the disposable native test with `python tests/m7/session.py`. This development ISO is not a completed M7 release.

[Initial native desktop evidence](../../evidence/M7/session/results.json) records the exact development build. M7 remains in progress until all owner-contract gates pass; these screenshots and document tasks alone do not close it.

## Current application slice

Editor and Calculator now load separate installed ELF programs into private CPL3 address spaces. Their state lives in bounded mailboxes, with checked display snapshots and brokered file actions. Faults and a hardware-timer budget contain bad/busy applications. Actual Calculator executable removal and offline reinstall preserve the required components and documents, including across restart. Native tests cover five negative app cases and return private allocations to baseline. [Architecture, choices and limits](../architecture/desktop-m7.md), [native app evidence](../../evidence/M7/isolation/results.json).

The compositor, Files and Settings remain trusted supervisor services; the event-worker application ABI is narrow. Networking/HTTPS, full interaction/resource/pressure qualification, supported desktop distribution options and final release publication remain pending. The development ISO is not a completed M7 release.

## Native network bootstrap slice

The original Intel 8254x Ethernet driver now performs real DMA/interrupt-driven traffic with automatic DHCP, ARP and DNS. A detached installed QEMU guest obtains its lease, resolves a real hostname, recovers from virtual cable loss, then returns to halted CPUs without continued painting or a permanent network polling timer. The positive profile explicitly exposes RDRAND (`max,x2apic=off`); the default QEMU CPU lacked that entropy source and correctly refused DNS randomization. That failed development case is retained. Hardware entropy is currently required for DNS; a broader entropy provider remains future work.

[Native packet/idle evidence](../../evidence/M7/network/results.json) and [30,000 deterministic parser mutations](../../evidence/M7/wire-results.json) qualify this bootstrap slice only. TCP, TLS, certificate/time checks and actual downloads remain pending. BearSSL portable compilation is preparation, not a working HTTPS claim. See [network design](../architecture/network-m7.md).

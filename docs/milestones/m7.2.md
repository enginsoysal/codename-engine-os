# M7.2 — installation to a usable folder desktop

Status: complete within M72-VM-v1; 12 exact-artifact host/runtime/repository gates pass.

Priority: two user-visible tasks, before additional applications: convenient native installation, then a real desktop with folder navigation. Product name remains **Engine OS**. M8 DOS/Windows compatibility is not started by this follow-up.

## Delivery

The new native setup includes a light/dark step layout, retained choices, guided disk selection and manager, optional guide, account/accent, explicit review, verified installation progress and **Open desktop**. The final action opens the actual persistent installed user volume immediately. A separate disk boot is required and tested to qualify independent startup. Recovery/Update preserves a compatible M7.1 volume.

Files starts on Home. A places sidebar, real path, Back/Forward/Up, named folder creation, paging, item count, protected system browsing, explicit deletion confirmation, taskbar and movable/resizable windows provide the focused desktop experience. Optional app work is deferred; Calculator is omitted from the standard installation and optional applications do not dominate the launcher.

A prepared VMware ZIP includes an ordinary relative-path VMX, a new empty growable 20-GiB SATA disk and the exact ISO. It is installed from scratch in tests. No changes to the user's VM or host desktop are made.

## Acceptance: M72-VM-v1

`python tests/m72/qualify.py` runs ten runtime gates against the exact media:

- Four BIOS/UEFI × ISO/USB native setup tasks: immediate persistent desktop, named folder navigation, independent CRC-checked metadata, twice detached boot without forced disk priority, and same-build ISO desktop resume.
- Disk management and destructive-consent regression: real FAT32 format, unrelated partition retention, nonblank-disk guidance and unchanged whole-disk hash when consent is unchecked.
- Low-memory Files tasks on 64-MiB/one-CPU and 128-MiB/two/four-CPU profiles: no retained-page growth or allocation failures during navigation, all CPUs halted and no idle repaint.
- Actual M7.1 installation through native M7.2 Recovery/Update, retained independently checked file bytes detached new desktop and retained-NVRAM rollback to the exact older desktop.
- Three VMware tasks: BIOS, UEFI, and the exact public VMware starter archive, all offline. They retain the same VMX/NVRAM and test normal optical-disconnected disk boot twice without boot-order overrides. Unrelated running VM inventory must remain unchanged.

A separate actual-C host gate decodes boot options and tests idempotency, foreign entry retention, denied writes and malformed/exhausted variables. Repository/source/proof validation is separate. [Exact aggregate acceptance](../../evidence/M7.2/acceptance-results.json) governs completion, including build/source/artifact hashes and immutable historical proof verification. A green development screenshot does not satisfy all gates. [Build and verification instructions](../../evidence/M7.2/README.md).

## Boundaries

The reported user's No Media screen was firmware, before Engine OS; its exact cause is not established. The old M7.1 disk boots in an unforced VMware baseline. The new default VM configuration and expanded persistent-VM tests reduce setup ambiguity; they do not prove every existing VMware configuration or physical device works. SATA/AHCI, 512-byte sectors, 2 GiB–2 TiB, Secure Boot off, original native extent volume and fixed install layout remain. Extra partitions are not auto-mounted. The initial desktop uses the installation kernel; later boots use the installed kernel.

# M4.5 SMP pressure-response correction

## Reproduced mechanism

The previous privileged native pressure probe sampled each AP timer count, kept an allocation admission budget active, and required every AP count to have advanced as soon as the short workload ended. The workload sleeps for three 10-ms clock ticks. A delayed VM CPU could therefore terminate the kernel after only about 30 ms, despite no architectural requirement for a hard 30-ms host scheduling bound.

The original exploratory trace lacks enough timing information to reconstruct its host scheduling history. Its failure message is retained. A separate controlled diagnostic reproduced that exact failure path: the test obtains AP1's host thread ID from the owned VM's QMP connection, verifies that the thread belongs to the owned QEMU PID, pauses only that thread briefly, and always resumes/closes it. The unchanged check then reports a missing timer at elapsed_ticks=3 and exits with the same SMP failure. No other VM/process/thread is suspended. Reproduction uses an isolated checkout of the recorded base commit plus the saved diagnostic patch (apply with `git apply --unidiff-zero`) and the current delay runner with `--legacy-check --expected-exit 99`; the source manifest verifies the exact diagnostic build identity. The exact diagnostic-only source patch and verified source identity are saved with [pre-fix evidence](../../evidence/M4.5/smp-delay/pre-fix-delay/results.json).

## Correction and synchronization

The pressure state machine now returns a pending status while an AP has not yet demonstrated fresh timer progress. The scheduler retains the reduced admission budget, releases its lock and waits with STI/HLT/CLI before rechecking under the lock. Remote timer handlers can complete instead of being blocked by a waiter holding the scheduler lock. No unbounded spin or additional per-request page allocation is introduced.

The first missing-progress observation starts a 100-tick bounded wait. Missing progress at that deadline still terminates the diagnostic workload. All five pressure intervals must finish with real AP timer-count increases. COW-OOM teardown uses the same path and restores the admission budget only after the response check finishes. The mechanism is shared by current M3 and M45 builds; historical release binaries are immutable. This is a privileged native verification operation, not a Windows/guest ABI or a hard real-time guarantee.

## Verification

The controlled short delay must now complete the native workload and exit successfully. A two-second AP suspension must still reach the SMP deadline failure. Repeated four-vCPU boots restricted to one host logical CPU exercise host contention; that restriction applies only to the newly created QEMU process. Full current M3 isolation/scheduling/VM/pressure/SMP regressions and the M4.5 boot/storage/input/trust suites qualify the shared change.

Exact build identities remain in each report; the diagnostic pre-fix build intentionally differs from the corrected acceptance build.

This closes a reproducible premature-failure mechanism without claiming every historical host event or every possible SMP defect is understood. Physical qualification and the remaining M4.5 hardware/trust tracks are separate.

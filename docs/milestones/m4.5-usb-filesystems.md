# M4.5 USB lifetime and extended read-only filesystem increment

M4.5 remains in progress pending the explicitly open qualification/trust tracks. This increment does not add an installer, arbitrary disk writes or Windows APIs.

## USB transport and lifetime

`kernel/input/xhci45.c` extends the original xHCI design in the M45 build; the published M4 driver stays separate. Direct root-port boot HID and SCSI transparent Bulk-Only mass storage share the controller/event ring. The mass-storage implementation owns command/data/status transfers, validates CBW/CSW signatures, tags, residue and completion lengths, and reads INQUIRY plus READ CAPACITY(10/16). READ(10/16) supports 512/4096-byte logical sectors. Only LUN zero and direct high/super-speed BOT devices are supported; UAS, hubs and arbitrary USB classes remain unsupported.

Each mass device adds seven managed pages: input/output contexts, control/IN/OUT rings, protocol buffer and data buffer. One request is outstanding and MSI completion sleeps with HLT and a bounded timeout backstop. Failure retains potentially owned DMA memory; successful Disable Slot completion precedes reclamation. Recoverable SCSI unit attention is cleared by REQUEST SENSE and bounded retry. Other command errors are reported; malformed transport or incomplete transfers quarantine the device.

Port-status interrupts only queue bounded work. Enumeration/disconnection runs outside interrupt context. Four live device contexts and 32 root-port bits bound state; unsupported candidates and allocation/disable failures are explicit. A failed disable retains the slot/pages. Successful disconnect retires the storage registry entry, drains events after disable, clears the DCBAA slot and frees the device's pages. A generation in each read callback prevents a retired entry reaching a reused device context. Up to sixteen storage entries, including retired diagnostic entries, are retained per boot; registry exhaustion is explicit rather than silently reusing a disk number. Generation exhaustion retires a context.

Named QEMU tests read real GPT/FAT32 payloads, wrap transfer rings, reconnect mass storage three times, reject the old disk reference, reconnect the keyboard, retain mouse input, contain a hot-attached read-EIO device and read a healthy replacement. They check exact page reclamation, unchanged backing hashes, four-CPU HLT and a two-second host-process CPU sample. This is not physical USB or hub qualification.

## Extended ext2 reader

`kernel/storage/ext2_read.c` provides a separate original read-only parser over ordinary registered disks and validated partitions. It accepts clean classic ext2 with 1/2/4-KiB blocks, 128/256/512-byte inode geometry and up to 256 groups. Explicit superblock feature allowlists reject journals, extents, 64-bit/flex metadata and other unsupported layouts. Indexed directory inodes and symlinks are unsupported. It validates table location/extent, inode and block references and directory record boundaries. Names remain exact validated UTF-8 without normalization/case folding; dot/dot-dot requests are rejected.

Twelve direct pointers and one indirect block support bounded reads and sparse holes. Directories are capped at 128 blocks and native file reads at 64 KiB. Console `extls N P PATH` and `extcat N P PATH` cap displayed files at 4 KiB. The existing marked 16-MiB development filesystem keeps its own previously qualified writable path; the new reader never exposes writes. Structural validation is not a full allocation-graph fsck, journal replay or arbitrary damaged-filesystem recovery.

Native tests use original fixed two-group fixtures, a known 64-KiB byte pattern crossing the indirect threshold, a zero-filled hole, a hard-linked UTF-8 path and explicit symlink/case/path/capacity boundaries. They exercise AHCI, NVMe with 4096-byte device sectors and USB, plus damaged pointer, directory, inode-table and unsupported-feature negatives. Temporary test payload mappings are removed and all eighteen pages reclaimed on success and failure. No external e2fsck qualification is claimed for these new fixtures. The implementation uses the published [superblock](https://www.kernel.org/doc/html/latest/filesystems/ext4/super.html), [classic block maps](https://www.kernel.org/doc/html/latest/filesystems/ext4/ifork.html) and [directory formats](https://www.kernel.org/doc/html/latest/filesystems/ext4/directory.html) as format references; this OS does not use the Linux kernel.

## Failure evidence and remaining boundaries

Separate persistent sector-zero EIO injection verifies AHCI, NVMe and VirtIO discovery reports an unreadable device rather than successful transfer. USB EIO is injected after normal firmware boot so the test actually reaches the native driver; a preboot USB read fault prevented firmware loading the ISO and is preserved as a fixture observation. A separate throttled USB backend exercises a real delayed DMA read and the native deadline. The driver retains all seven device pages during timeout, remains responsive, and frees them only after completion/Disable Slot; a healthy replacement reads again. This is not exhaustive electrical/removal-under-DMA or physical timeout qualification.

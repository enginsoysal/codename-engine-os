# M6 — real product installation

Status: **complete within M6-VM-v1**. [Owner acceptance contract](../roadmap/milestones.md), [exact artifact acceptance](../../evidence/M6/acceptance-results.json), [release](../releases/m6-v0.6.0.md). ## Implemented delivery

- A native graphical Back/Next/Finish wizard with disk selection, retained choices, account-name/accent setup, optional guide, destructive review, verified progress and readable failures. Keyboard, USB mouse and PS/2 mouse routes are implemented; ordinary installation needs no terminal commands. Advanced terminal/details remain available.
- A shared capacity planner and actual GPT/BIOS/EFI installation using the selected eligible SATA disk. The data partition uses the remaining aligned capacity; boot code and system bundles live on the installed disk.
- Original streaming copy-on-write storage replacing the old 16-MiB/48-KiB profile, with independently checked metadata and file integrity. A large document survives media-detached reboot.
- Persisted local user preferences and native user directories. Optional guide removal is independent of base/other files. Calculator and the desktop are M7 work; no executable package manager is claimed from a data-file checkbox.
- Two verified system-bundle slots, redundant generation/checksum activation records, actual different-build update, rollback and ISO-assisted boot repair. An interrupted boot replay can require the ISO; automatic bootloader A/B failover is not claimed.
- Validated custom distro input for branding/accent/default guide and selected data files. User-template paths map to the selected account. Unsupported shell hooks/executable packages remain rejected.

## Acceptance gates

Run the actual kernel/installer in named QEMU BIOS/UEFI ISO/USB and VMware BIOS/UEFI SATA profiles. Qualify guided install, independent GPT/FAT/kernel/data inspection, multiple media-detached boots, files larger than 48 KiB, persisted customization, cancellation/refusal, optional removal, two distinct kernel builds, rollback, corrupted boot repair and interrupted writes/activation. Record CPU halt and peak/retained memory separately from static kernel/firmware resources. No mockup, native probe or splash alone closes the milestone.

The acceptance report must bind every successful report to the exact candidate source/build/media digests. Initial arithmetic/C host tests alone do not qualify installation. Earlier M0–M5.1 accepted reports and releases remain unchanged. Failed development checks remain under the M6 history directory.

## How, why and limits

[Native storage and system-slot decisions](../architecture/storage-m6.md) explain mechanism, alternatives and fault boundaries. [Installation handbook](../handbook/install-m6.md) provides the real user workflow. The original [browser design](../handbook/installer-design.md) remains a design reference, not native evidence.

The initial install path is x86-64 SATA/AHCI with 512-byte sectors, 2 GiB to 2 TiB arithmetic bounds. Runtime qualification names actual tested capacities, firmware and virtual devices. Media is unsigned: disable Secure Boot. The volume has 1,024 file/directory entries, 255-byte paths, contiguous extents and bounded copy-on-write workspace. Local profile setup does not implement authentication, ACLs or multi-user security. No desktop, Windows/MS-DOS application compatibility, universal hardware support, cross-layout migration or arbitrary physical power-loss guarantee is claimed.

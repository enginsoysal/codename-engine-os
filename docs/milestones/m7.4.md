# M7.4 — independent standard applications

Status: the first bounded application delivery is qualified within M74-VM-v1.
[Exact acceptance](../../evidence/M7.4/acceptance-results.json) records thirteen
gates and preserved historical proof. Expanded app capabilities and desktop
integrations remain explicit follow-ups; building media alone is not qualification.

The owner requested the proposed standard application set, attractive native UI,
convenient ordinary tasks, bounded memory use and safe independent removal.
This follow-up precedes M8 and does not implement Windows application compatibility.

## Requested applications

Files, Settings, Calculator, Text Editor, Terminal, Clock, Calendar, System
Monitor, Disk Utility, Software Manager, Update & Recovery, Archive Manager,
Image Viewer, Screenshot, Media Player, Browser and Help are in scope.
Downloads remains a separate existing utility. Desktop search, notifications,
volume/network controls, safe eject and Trash need explicit implementation
and acceptance rather than an icon or a mock window.

## Architecture and acceptance

- Keep boot, storage, the time service, compositor, package broker, Files and
  Settings in the protected base. Optional applications depend on these public
  services; the base does not depend on an optional application.
- Preserve stable package identities in the native catalogue. A deferred
  catalogue identity is not an installed or completed application. Only working
  applications may appear in the ordinary launcher.
- Install optional packages and retain verified offline reinstall sources.
  Actual CPL3 programs use separate ELF files; fixed broker frontends use exact
  validated declarative manifests rather than idle/no-op processes. Load worker
  code on demand, share it between same-app windows and release it after last
  close. Trusted native UI/file operations
  still belong to the shared supervisor broker; that static memory must be
  reported separately, not described as removable app RSS.
- Plan removal, show the exact application, retain private data and shared
  documents, reject active instances, and never silently remove another package.
  Settings must retain package management if Software Manager is removed.
- Use real file formats and real device/network operations. Unsupported codecs,
  websites, encodings and file sizes must be explicit; a placeholder screen
  cannot satisfy an application gate.
- Review each surface for clarity, convenience, user friendliness, graphical
  quality and readability at ordinary and actual native 4K resolutions.
- Check every optional application omitted at installation, installed, opened,
  used, closed, removed, reinstalled and used after an independent disk restart.
  Verify resulting files independently and measure retained/peak allocations,
  idle wakeups and app code page release.
- Preserve historical binaries and frozen evidence. Use `build/m74`,
  `evidence/M7.4` and `EngineOS-M74` artifacts only.

## Implemented application slice

All catalogue applications now have real native functions: the existing Files,
Settings, Editor, Terminal, Downloads and Monitor join decimal/scientific/
conversion Calculator, Clock, local Calendar, Help, Software Manager,
disk/recovery frontends, BMP viewing, framebuffer screenshots, a bounded CPL3
ZIP decoder, a basic HTML/text HTTPS Browser and PCM WAV/HDA playback.
Functionality is deliberately bounded and documented in the [app guide](../handbook/apps-m74.md).
A basic browser is not modern web compatibility; WAV/BMP/ZIP do not imply every
media/image/archive codec. Calendar reminders, synchronized accounts, richer
editor capabilities and additional desktop integrations remain follow-ups.
They are not claimed as implemented by the first app delivery.

Native development evidence covers actual HTTPS, file extraction and CRCs,
package removal/reinstall, private-data retention, independent disk startup,
actual 4K surfaces, low memory and a no-optional-apps distribution. [Exact-artifact acceptance](../../evidence/M7.4/acceptance-results.json)
qualifies the first delivery; [release files](../releases/m74-v0.7.4.md) identify
the matching artifacts.

The PC time service uses the RTC update-ended interrupt once per second, while
timer/stopwatch durations use the existing monotonic HPET clock. It does not
enable a continuous high-rate UI polling timer. A timer may continue after its
window closes; app removal cancels its optional background state. Session alarms
currently display a message without sound and are not persisted across restart.
These limitations must remain visible until corresponding work is completed.

## Runtime design and limits

Hardware is bound through supported bus/class/protocol interfaces, not a required brand/model table. A virtual device is a real protocol endpoint from the kernel's perspective. Discovery, initialization, verified transfer and unavailable/unsupported/error states remain distinct; recognizing a class alone does not implement its driver.

Ordinary disks stay read-only. Only the validated, marked M4 development volume retains its bounded ext2 write path. GPT is bounded to 128 entries; MBR extended/hybrid layouts, NTFS/exFAT mounting and unsupported filesystem features are refused. USB admits eight device contexts and five route nibbles, with one selected xHCI controller. UAS is read-only LUN zero. Exact other quotas and unsupported profiles remain in the linked contracts.

The public final media are unsigned: use Secure Boot disabled. The accepted enabled-Secure-Boot route uses separate local owner-signed UEFI media and disposable enrolled QEMU policy. It does not claim factory trust. VMware qualification covers boot/native completion/storage reads; USB/HID/fault/idle detail is qualified in the named QEMU profiles, not every VMware configuration.

## Explicit follow-up tracks

Physical firmware/controllers/input, physical power/idle measurements, production PK/KEK/image-key custody/enrollment/recovery and OEM/Microsoft factory trust remain **unqualified and outside M45-VM-v1**. Their [physical procedure](m4.5-physical-qualification.md) remains available for later work. ARM64/Raspberry Pi remains M16. Completion is not universal hardware or arbitrary hypervisor-version support.

Installation, partitioning/formatting, target selection, installed-system boot and update activation/recovery remain M5, which has not started. Desktop/network/GPU acceleration and Windows 95–11, Linux/macOS applications remain later milestones. There is no installer or app compatibility in this ISO.

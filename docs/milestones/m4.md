# M4 — storage, discovery and input

**In progress.** The first increment implements an original AHCI block driver and a kernel diagnostic console. It is not M4 acceptance: writable filesystem/VFS, file create/rename/locking/recovery, USB HID and mouse remain pending. M3 is the latest completed milestone. Windows 95–11 binary compatibility remains a later requirement.

## First increment: how and why

PCI configuration-space traversal follows bridges and binds class/subclass/programming interface `01/06/01`, without vendor/model matching. The register/FIS/DMA interface follows the [Intel AHCI 1.3.1 specification](https://www.intel.com/content/dam/www/public/us/en/documents/technical-specifications/serial-ata-ahci-spec-rev1-3-1.pdf). This exercises real kernel-owned storage after ExitBootServices; firmware media authoring is separate. NVMe, virtio and physical controllers are unqualified.

One slot, one outstanding 512-byte request, four managed DMA pages (16 KiB), a fixed command list/FIS/table/bounce buffer, LBA48 reads/writes and FLUSH CACHE EXT keep ownership and resource costs bounded. Bootstrap and console commands use bounded synchronous polling; interrupt-completed block queues remain pending. CPU idle uses interrupt-driven input and `sti; hlt`, without a storage polling loop. Timeout offlines the port and quarantines its DMA pages: stopping a command is attempted, but is not treated as proof of completed DMA. No reclamation follows an uncertain timeout.

Before writing, IDENTIFY must report the exact 16 MiB/512-byte-sector test profile, and sector 0 must contain our versioned marker, capacity and CRC. Writes are hard-coded to sector 1. The record has a generation, bounded text and CRC; store writes, flushes, rereads and compares the entire sector. Neither successful flush nor CRC makes a sector atomic under power loss. A corrupt record is refused; recovery/journaling is not implemented. This intentionally small transport probe precedes filesystem work and does not replace the [directory/VFS design](../architecture/filesystem.md).

PS/2 set-1 US ASCII and COM1 receive interrupts feed a fixed 256-byte queue; overflow is counted. Input handlers do no drawing or disk I/O. The consumer renders a bounded framebuffer text grid and mirrors output to serial. Shift and Backspace work; Unicode, alternate layouts, history, Caps Lock, USB and mouse do not. This diagnostic console runs in the kernel; it is not the future user shell or desktop. The native M2/M3 qualification phase still runs before it.

## Build and test

```powershell
python tools/build/m4.py
python tests/m4/boot.py
python tests/m4/console.py
python tests/m4/verify.py
python tools/vm/run.py --milestone M4 --create-data-disk
```

The QEMU launcher creates a new marked `build/m4/manual/data.img` only if absent, then preserves it between launches. `--data-disk` selects an existing marked regular `.img` file. Never use host devices. The default launcher remains M3 until M4 is complete. M4 QEMU uses the virtual PS/2 keyboard instead of USB HID.

Commands: `help`, `info`, `show`, `store TEXT`, `sync`, `halt`. For example, enter `store Hello`, close the VM, boot with the same data image and enter `show`. Without a marked SATA volume the console works with storage writes disabled. Command length is capped at 120 ASCII characters; stored record payload is capped at 120 bytes (114 through the console command).

For VMware, use an EFI x86-64 VM, Secure Boot disabled, HPET enabled, 128 MiB RAM and a SATA controller. Load `dist/EngineOS-M4.iso`. Copy **both** `EngineOS-M4-data-template.vmdk` and `EngineOS-M4-data-template.img` to a disposable VM directory, keeping their names together, and attach the copied VMDK as a SATA disk. Keep the published/build template unchanged; each VM needs its own writable copy. Two AHCI persistence boots pass on Workstation 26.0.1 with two vCPUs; see the separate [VMware report](../../evidence/M4/vmware-report.json). Reproduce with `python tests/m4/vmware.py`. VMware input/framebuffer and other versions/device profiles remain unqualified.

## Acceptance still outstanding

- Writable filesystem/VFS and the planned namespace, metadata, case/Unicode and handle semantics.
- Persistent file create/read/modify/rename, locks/delete, disk-full handling and documented crash recovery.
- Interrupt-completed block queues and broader device/error/timeout qualification.
- Native USB controller, keyboard and mouse on named profiles.
- Full M4 resource, VMware and regression acceptance, followed by the installation milestone M5.

See [current evidence](../../evidence/M4/README.md). No installer, desktop, Windows loader or application compatibility is included.

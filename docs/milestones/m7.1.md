# M7.1 — installer disk and partition management

Status: in progress. M7 v0.7.0 remains the accepted desktop release until exact M7.1 acceptance and publication. Original DOS/Windows support remains M8. The owner encountered an existing-disk refusal with an unhelpful generic message; this milestone closes that installer workflow.

## Acceptance contract

The native installer must offer an ordinary Manage disks screen, distinguish no selection from existing contents/unsupported geometry/I/O failure, and preserve a safe cancel path. It must show disk number, controller/port, capacity, partition scheme, partition names/formats/sizes, protected entries and aligned free space. Selection and review never write.

Implement creation/deletion of GPT and primary MBR data partitions, actual FAT32 and original Engine data quick formats, blank-disk GPT initialization, verified GPT-copy repair, and explicit whole-disk metadata clearing. Every mutation requires a review showing the selected disk and affected partition, an unchecked consent box and Apply. The default Keep/Cancel action writes nothing. Existing Engine OS system partitions and extended MBR containers are protected against individual deletion/formatting.

Fresh Engine OS installation still owns the whole selected disk. A separate Erase and install choice allows a previously partitioned disk to proceed through Components, Style and Review without changing it. The final review requires explicit whole-disk consent before metadata clearing and actual installation. It must then boot the native desktop without media and preserve a newly saved document across restart.

## Deliberate scope

SATA/AHCI with 512-byte logical sectors remains the writable transport. Inspect/edit canonical GPT with 128 128-byte entries; display primary MBR entries and preserve extended containers without pretending to manage logical partitions. Unsupported or inconsistent tables are read-only until explicit repair or whole-disk replacement. No filesystem resize/move, non-destructive conversion, NTFS/ext formatting, logical-MBR editing, secure erasure or installation alongside another OS is claimed.

FAT32 requires at least 64 MiB; the original Engine data format requires an aligned partition of at least 1 MiB. This is data formatting, not an independently bootable Engine OS installation. Whole-disk installation keeps its 2-GiB minimum and fixed BIOS/EFI/two-slot/data layout. Existing partitions are preserved by operations on another data partition; whole-disk replacement deliberately removes all old partition access after confirmation.

## How and why

Use an original freestanding C backend with bounded sector callbacks and a separate trusted graphical adapter. The same C runs in host fault tests and the native ISO. Inspect both GPT copies with header/table checksums, entry range/overlap/GUID checks and conservative edit refusal. Write backup metadata first, flush, then primary and flush; mixed generations require an explicit choice rather than a guessed winner. This is not an atomic partition-table or physical power-loss guarantee.

Plans capture the selected disk identity, metadata fingerprint and format boot-sector identity; commit revalidates them. All transfers are at most 4 KiB. Reuse the installer's existing native-volume workspace for formatting instead of allocating another metadata volume. A quick format writes filesystem allocation/namespace metadata, not a disk-sized buffer. Prior published artifacts and accepted evidence remain frozen.

## Required proof

Actual C host tests with independent GPT/FAT decoding, exact foreign payload/entry preservation, stale/forged-plan refusal, changed metadata, corrupt mirrors and every refused/torn write/flush position. Native graphical tests must operate GPT and MBR fixtures, cancel/unchecked confirmations, format both filesystems, delete/create a partition, protect Engine OS system partitions, replace an existing disk and reach the detached desktop. BIOS/UEFI, USB media, a real owned VMware run, a separate distro, resource/idle checks and a repeated-install case bind final media. Documentation, release/checksums and the BrixCanvas user guide must identify the exact scope.

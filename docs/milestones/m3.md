# M3 — scheduling, memory policy and concurrency

M3 is complete within the qualified **native x86-64 VM scope** described here. Completion requires the fresh [acceptance report](../../evidence/M3/acceptance-results.json), not this statement alone. [Evidence](../../evidence/M3/README.md), [release](https://github.com/enginsoysal/codename-engine-os/releases/tag/m3-v0.3.0), [roadmap](../roadmap/milestones.md).

## Boot and what you see

```powershell
python tools/build/m3.py
python tools/vm/run.py --milestone M3
python tools/vm/run.py --milestone M3 --cpus 4 --ram 64
python tools/vm/run.py --milestone M3 --usb
python tests/m3/verify.py
```

The current launcher defaults to M4; explicitly select M3 for this milestone. M3 uses two vCPUs and 128 MiB by default; select `--cpus 1`, `2` or `4`. Historical M2 remains available with `--milestone M2` and one CPU. Generated files live in ignored `build/m3/` and `dist/`; source/evidence stay in their dedicated directories.

For VMware, power the VM off, attach `EngineOS-M3.iso` to the CD/DVD drive and connect it at power on. Use 64-bit UEFI, Secure Boot disabled, two vCPUs and 128 MiB initially. The earlier FreeBSD guest label selected a firmware configuration; Engine OS supplies its own kernel. Pinned qualification is QEMU q35/OVMF/TCG with ACPI MADT, xAPIC and 64-bit HPET. Additional [automated VMware Workstation 26.0.1 serial/runtime cases](../../evidence/M3/vmware/README.md) pass on 1/2/4 CPUs with 128 MiB, EFI/FreeBSD-64 profile and HPET enabled; graphical capture is QEMU-only. One low page at physical 0x8000 must be available for the startup trampoline; failure is diagnosed. No host/real disk is required. The isolated VMware test explicitly sets `hpet0.present = "TRUE"` in its own powered-off VM configuration.

The screen identifies `M3 KERNEL ONLINE` and reports isolation, `THREADS WAITS VM SMP: PASS`, active CPUs, native thread starts and peak/retained managed RAM. The workload runs automatically, reaps user resources, stops periodic timers and halts every CPU. There is no installer, shell, keyboard handling, desktop or Windows application execution. Installation remains M5; desktop remains M6.

## Architecture, how and why

| Mechanism | Implemented method | Choice and boundary |
|---|---|---|
| Threads/processes | Eight generation-tagged thread slots, two address spaces, independent guarded 4 KiB stacks and 4 KiB TLS pages, shared process data/handles/mailbox | Bounded accounting and real shared address spaces; no thread migration or unbounded process loader |
| CPU context | General registers, safe arithmetic/direction flags, FS-base TLS and aligned FXSAVE64/FXRSTOR64 state for x87/MMX/XMM/MXCSR | Eager state ownership avoids lazy-FPU leaks. OSXSAVE is disabled; AVX/AVX-512/extended XSAVE state is unsupported |
| Scheduling | Timer-driven round robin on each CPU, one fixed CPU affinity per process; kernel dispatch serialized by a lock | Processes execute user instructions on separate cores; one process's mappings/threads remain on its owner CPU. Load balancing and kernel preemption are later optimizations |
| Time | ACPI-discovered 64-bit HPET, quantized approximately 10 ms monotonic deadlines | Time continues across delayed/missed interrupts; timer delivery is not treated as elapsed time. A masked-interrupt probe verifies catch-up |
| Timer delivery | Approximately 100 Hz PIT on BSP; calibrated local APIC periodic timers on APs | Simple bounded baseline. Sleeping schedulers use atomic interrupt-enable/HLT rather than polling; tickless idle is future work |
| Waiting | Atomically test/enqueue under the scheduler lock; manual/auto-reset events, message waits, sleep, join, timeout, cancellation and handle-close wakeups | Fixed tables bound scans. Native waits are implemented; Windows wait-any/all/APCs/futex semantics remain adapter work |
| Objects/IPC | Sixteen process-wide slot/generation/rights handles, 32 referenced event/memory objects, four-message mailbox, explicit mapping references | Duplicate/transfer cannot increase rights; shared map outlives its handle; no credentials/ACL subsystem yet |
| Anonymous VM | One reserved 16-page window per space; explicit backed commit/decommit, rollback on partial allocation failure, zeroed reuse, reference-counted snapshot/COW mappings | No overcommit guarantee. COW is resolved both on CPU write faults and checked kernel copy-out. This is a bounded anonymous-memory API, not a disk loader/fork implementation |
| Pressure/OOM | Explicit allocator admission budget, checked no-memory returns, four pages held as an emergency reserve, allocation-free fault cleanup | Test budget reduction is restricted to explicitly privileged native harness threads. Failed commit/thread/process allocation rolls back; COW backing failure terminates that thread and restores the test budget |
| Additional CPUs | Checksummed ACPI MADT discovery, INIT/SIPI trampoline, per-CPU GDT/TSS/guarded entry and IST stacks, APIC timers and IPI mailboxes | Qualified at 1/2/4 active CPUs, with native CPL3 execution observed on every active CPU. x2APIC, hotplug, arbitrary firmware/physical systems are not qualified |
| Synchronization/TLB | Scheduler lock before allocator lock; allocator zeroing outside its bitmap lock; IPI invalidation acknowledgements before shared supervisor pages are freed | User spaces are affinity-bound, avoiding remote active user mappings. Shared kernel-mapping replacement is tested on all APs |

Implementation: [scheduler/runtime](../../kernel/scheduler/m3.c), [SMP/clock](../../kernel/arch/x86_64/smp.c), [AP entry](../../kernel/arch/x86_64/ap.S), [allocator](../../kernel/memory/pages.c), [native probes](../../user/m3.c), [ABI constants](../../include/engine/user.h).

Kernel entry remains non-reentrant on each CPU, with IF cleared through dispatch; blocked schedulers release the lock before `sti; hlt; cli`. The kernel does not keep a separate blocked C call stack for each user thread: resumable state is in bounded thread records, while each CPU has a guarded entry stack. The lock is never held while awaiting another CPU's work completion. This prioritizes correct lifetime/ownership and low resident cost before fine-grained scalability.

## Native API and policy

The original `int 0x80` transport and checked buffers remain. M2's handle/IPC/isolation workload is retained, and the thread runtime also implements rights-checked duplicate/close/transfer, event query and shared-memory create/map. PID identifies an address space; the new TID call identifies a generation-tagged thread. Send/transfer accept a process ID or an explicit thread token naming its process mailbox/table. There is one verification security group, not a general identity system.

Thread creation takes an executable entry address, output token pointer and entry argument; the kernel validates mapping/permissions, allocates stack/TLS and initializes a fresh CPU context. The entry function must use the native thread-exit operation instead of returning. Ordinary created threads do not inherit privileged harness-budget controls. Join consumes a zombie slot; stale tokens are rejected and generation wrap retires slots. Process exit cancels remaining threads before the last address-space reference is destroyed.

The anonymous VM window starts at `USER_BASE+0x80000`. Reserve takes a page count (1–16); commit/decommit take page offset/count and check overflow/range/overlap. Commit supplies zeroed backing immediately and rolls back the entire new range on failure. Decommit drops mapping references, allowing recommit with zero contents. Snapshot creates a separate address space with references to committed anonymous pages; both maps become read-only until private-write resolution. Shared object mappings are a separate explicit mechanism. The bootstrap snapshot launch and pressure/clock probes are privileged harness operations, not guest Windows APIs.

Close wakes waits on that handle with cancellation; manual-reset signaling wakes all object waiters, auto-reset signaling wakes one or retains a pending signal. Deadlines are monotonic hardware-clock ticks, bounded to 1000 ticks per request or an explicit infinite wait. A zero timeout polls. The privileged launch owner can join its cross-CPU snapshot thread; unjoined terminal records are reaped when their owner exits. Join timeout does not destroy the target; thread cancellation and process exit do. Native status codes remain separate from future Windows/Linux/Darwin translation.

## Acceptance and measurements

Every successful boot must complete both the inherited workload (47 starts, 37 exits, ten isolated hostile faults including the preemption pair) and the M3 runtime (85 thread starts: 73 exits, ten cancellations including deliberate OOM containment, two isolated faults). These are distinct categories, not 85 processes. The suite also requires:

- x87/XMM0/XMM15/MXCSR/TLS isolation and AP SIMD resume; actual native execution mask for every active CPU.
- Signal-before-wait, wait-before-signal repeated 32 times, manual-reset multiple waiters, auto-reset consumption, timeout, close/cancel, stale tokens, eight-thread and sixteen-handle limits, allocation rollback and mailbox blocking.
- Two CPU COW write resolutions, one kernel-copy COW resolution, private parent/child contents, zeroed recommit, commit/snapshot/thread no-memory rollback, one contained COW-OOM fault and five pressure-responsiveness intervals.
- Concurrent allocator zero/reuse/accounting on all CPUs; AP timer progress; acknowledged shared-kernel TLB replacement/unmap; all event/backing/page references balanced.
- HPET progress with interrupts masked, HLT during waits, and no early deadline wakeups. A separate single-CPU instruction-counted QEMU case enforces a five-tick lateness budget under a controlled virtual clock. Raw multi-core lateness is reported without a hard real-time ceiling; an earlier timing-gate failure is retained in [history](../../evidence/M3/history/README.md).

[Boot report](../../evidence/M3/boot-results.json) contains 14 cases: ISO/USB, 64/128/512/2048 MiB, 1/2/4 CPUs, repeated four-CPU runs, a deterministic-clock case, firmware-exit retry and three failure routes. Five visual/idle/debugger checks observe all four CPU halt states and actual framebuffer output. Five repository gates plus all 51 M0 checks remain required; M2 is separately rebuilt/requalified as a regression.

Managed memory budgets: peak at most 512 KiB; retained baseline `(15+8*(active_cpus-1))*4096` bytes, currently 60/92/156 KiB for 1/2/4 CPUs. The extra 32 KiB per AP is its retained guarded entry/IST backing. Boot reservations are separately capped at 1 MiB; managed peak plus boot at most 2 MiB. Exact observed values and runtime-only peak are in the reports. Firmware, devices, framebuffer and host memory are excluded, not silently called kernel pages. Native thread cost is reported as metadata plus one stack and one TLS page, excluding shared process/code costs.

The same two SIMD/TLS probe threads also perform a gated 40-yield exchange each. Sixty-four middle samples (excluding four initial/final iterations per thread) measure the complete two-thread native yield round trip, including trap/save/scheduler/restore, peer instrumentation and possible interrupt overhead. Raw min/p50/p95/max TSC deltas are reported; they are not one-way hardware cycle estimates. Same-address-space selections avoid redundant CR3 writes/TLB flushes; explicit mapping invalidations remain mandatory and tested.

Return-preparation reporting separately uses 256 bounded samples after 16 warmup selections, with min/p50/p95/max TSC deltas for map/FS/FX restore and return preparation. It excludes trap entry/complete user-to-user round trip and is an emulator observation, not calibrated hardware CPU cycles or nanoseconds. CPU idle sampling covers a reported two-second host-QEMU interval after all timers are stopped; it is not a desktop/power benchmark. No claim of globally optimal resource use follows from these measurements.

## Remaining product work

M3 closes its native VM acceptance gate, not general hardware or application compatibility. Future work includes migrating/load-balanced threads, finer locking, extended XSAVE state, tickless scheduling, reclaim/cache/file-backed demand paging, swap/compression and broader fault/race testing. Storage/input is M4, real installation M5 and desktop/network/downloads M6. Windows 95–11 remains the unchanged [WC1–WC7 requirement](../roadmap/windows-compatibility.md), with no original Windows applications yet qualified.

The earlier [preemption-only alpha](https://github.com/enginsoysal/codename-engine-os/releases/tag/m3-preemption-alpha.1) remains historical. Its incomplete scope is not the final M3 release.

Primary references: [Intel system programming/instructions](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html), [Intel 8259A](https://www.scs.stanford.edu/11wi-cs140/pintos/specs/8259A.pdf), [QEMU monitor](https://www.qemu.org/docs/master/system/monitor). References describe hardware; the linked fresh reports establish only the tested implementation behavior.

Mailbox publication can precede IPI delivery. Each AP therefore performs the requested shared-page invalidation in the worker before acknowledging it, even if an earlier interrupt already invalidated the page. The SMP test deliberately delays doorbells and reports completions before delivery, exercising this ordering rather than assuming every worker woke from that IPI.

A negative-control ISO patches only the named shared-invalidation helper into an immediate return, leaving normal release artifacts unchanged. It must fail with the stale-TLB diagnostic on two CPUs after the normal native workload. This proves the delayed-doorbell scenario detects missing worker invalidation; expected failure is recorded as a successful negative-control test, not normal-boot qualification.

CPU identity uses kernel-programmed/read-back IA32_TSC_AUX with RDTSCP when advertised, with APIC-ID lookup as a fallback. HPET is read for timer delivery, time/deadline operations and wake/cancel ordering; ordinary yield/lookup/allocation paths do not poll it. This preserves elapsed-time correctness while removing avoidable device accesses from context switches. The same user round-trip binary measures the optimization; comparisons remain scoped to the recorded host/hypervisor.

## Pressure-response correction

Current builds replace the immediate AP timer-count assertion with a bounded, interruptible response check while the admission budget remains active. The scheduler lock is released across HLT waits. Five intervals and actual AP progress remain mandatory; short-delay and deadline-failure injections distinguish temporary host scheduling delay from missing progress. See [causal evidence and limits](m4.5-smp-pressure.md). Historical release binaries remain unchanged.

# M3 — scheduling, memory policy and concurrency

Status: **in progress**. The first increment implements single-CPU native preemption; the complete M3 acceptance gate is not closed. [Roadmap](../roadmap/milestones.md), [evidence](../../evidence/M3/README.md).

[Download the preemption increment](https://github.com/enginsoysal/codename-engine-os/releases/tag/m3-preemption-alpha.1). This prerelease is deliberately separate from a completed M3 release.

## Build and observe the first increment

```powershell
python tools/build/m3.py
python tools/vm/run.py --milestone M3
python tests/m3/verify.py
```

Generated normal media: `dist/EngineOS-M3.iso` and `dist/EngineOS-M3-usb.img`. Use one vCPU, 128 MiB RAM, 64-bit UEFI and Secure Boot disabled. For VMware, power off, replace the CD/DVD ISO, connect at power on and boot the EFI optical drive. Automated qualification is QEMU only; VMware remains a separate user test. No physical or host disk is required.

The screen identifies `M3 PREEMPTION INCREMENT`, reports timer preemption and inherited isolation results, then halts. It has no installer, desktop or keyboard interaction. Serial output contains the measured preemption count and memory totals. The default launcher still selects the completed M2 baseline unless M3 is explicitly selected.

## Implemented first increment: how and why

The bootstrap CPU uses the legacy PC PIT channel zero in rate-generator mode with divisor 11932 (approximately 100 Hz). The cascaded PIC is remapped to vectors 32–47, with only IRQ0 unmasked. Interrupt gates clear IF on entry; the kernel keeps interrupts disabled through dispatch and CR3 switching, so the shared guarded entry stack remains non-reentrant. User return enables IF only during the new preemption phase. Each timer interrupt acknowledges IRQ0 and runs the bounded round-robin selector.

This is an explicit temporary PC-VM baseline, not the final SMP clock source. It isolates interrupt delivery and context correctness before adding APIC discovery, per-CPU stacks and concurrent kernel access. A lower tick rate limits interrupt overhead; this increment does not claim optimal latency or tickless operation. PIT/PIC-only hardware coverage is limited. The controller programming follows Intel's [8259A datasheet](https://www.scs.stanford.edu/11wi-cs140/pintos/specs/8259A.pdf); per-CPU APIC timers are the next hardware step.

Preemption must retain interrupted arithmetic and direction flags. The return path preserves CF/PF/AF/ZF/SF/DF/OF while enforcing native selectors, safe RIP/stack, IF and reserved flags; it clears debug, I/O privilege and other unsupported control state. M2's existing deterministic cooperative phase retains its original policy. Kernel entry clears DF before C code. Only general-register native probes are supported; FPU/SIMD state isolation is still required before general programs.

After all 45 M2 probe starts and cleanup, two fresh isolated processes map one explicit test coordination page. One repeatedly increments a counter; its peer can advance a 16-step handshake only after observing new counter progress. Neither uses yield, sleep or polling syscalls inside the handshake. Timer switches are therefore necessary for completion on the one active CPU. A carry-dependent assembly probe also exercises interrupted flags. Both exit normally; the temporary page and private resources are reclaimed. These busy loops deliberately stress preemption and are finite test workloads, not the intended waiting API.

The expected combined totals are 47 starts, 37 clean exits, ten isolated hostile faults, at least 16 timer preemptions and zero assertions/accounting failures. The legacy `M2_STATS` and `M2_ISOLATION_PASS` serial markers identify the reused isolation/accounting implementation; `M3_PREEMPTION_PASS` is the additional gate. No universal starvation/latency claim follows from this workload.

The timer is masked after the finite workload and the CPU executes HLT. Existing peak/retained/boot memory budgets remain enforced. No new per-process stack or timer object is allocated for the interrupt path; the coordination page is test-only and freed. Host CPU sampling is a halted-demo observation, not a desktop or hardware power benchmark.

## Remaining M3 steps and acceptance

1. Save/restore supported FPU/SIMD state; define feature exposure and TLS/thread context. Test independent register patterns across involuntary switches.
2. Separate threads from process address spaces and handles; add bounded lifecycle/cancellation and teardown tests.
3. Implement atomic scheduler-backed event/message waits, monotonic deadlines and interrupt-aware idle. Test signal-before-wait, wait-before-signal, timeout/cancel/exit and lost-wakeup races.
4. Add reserve/commit/decommit, reference-counted shared/COW backing, fault resolution, quotas, emergency reserve and pressure/OOM policy. Verify accounting, isolation, low-RAM failures and responsiveness.
5. Discover/start additional CPUs; provide per-CPU entry/IST/timer state, locks, ordering and TLB shootdowns. Qualify one and multiple active CPUs; merely configuring extra vCPUs is insufficient.
6. Measure switch cost, resident bytes/thread, scheduling/deadline latency and pressure behavior. Publish full fresh regression, ISO/USB and visual/idle evidence before marking M3 complete.

Each step updates contracts, decisions and evidence with the code. M4 storage/input, M5 installation and M6 desktop remain later milestones. Windows 95–11 requirements, including Win16/PE32/PE32+, remain in [WC1–WC7](../roadmap/windows-compatibility.md). This increment adds no Windows APIs or original application support.

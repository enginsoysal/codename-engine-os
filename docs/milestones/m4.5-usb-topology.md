# M4.5 bounded USB topology and UAS

The original shared M45 USB stack lives in `kernel/usb/xhci.c`; M4 retains its separate historical HID driver. It binds by xHCI/USB class and protocol, without vendor-name tables. This increment remains read-only for ordinary storage and is not universal hardware qualification.

## Hub lifetime

USB 2 class-9 hub control/status requests power and reset ports, configure the xHCI hub context, construct route strings, and defer child enumeration from interrupt completion to the existing worker. Eight device contexts are a fixed admission bound; DMA pages are allocated only for attached devices. Route depth is capped at five nibbles and downstream ports at fifteen. Transaction-translator fields are populated for low/full-speed descendants of high-speed hubs, but that physical profile has not been qualified. SuperSpeed hubs are explicitly unsupported.

Children are retired before their parent. If Disable Slot fails, pages and the necessary parent context remain retained rather than being reused while hardware could still reference them. Existing storage generation checks reject old disk references after reconnect. Hub power/overcurrent status retires children and reports a diagnostic.

Pinned QEMU full-speed hub tests cover a direct hub and five hubs in a chain, real FAT32 reads, keyboard/mouse input, three storage reconnects, EIO replacement, and populated-tree unplug/rebuild. The eight-device chain retains 360 KiB of managed pages, peaks at 456 KiB, and releases exactly 42 device pages on whole-tree removal. These counts exclude firmware, framebuffer, reserved boot resources and emulator memory. Every profile independently checks HLT on four CPUs and samples emulator CPU time; these are not physical power measurements.

## Read-only UAS

USB class 08/subclass 06/protocol 62h is parsed with Pipe Usage descriptors and SuperSpeed endpoint companions. High-speed uses Ready/Sense IUs; SuperSpeed uses primary stream contexts and concurrently posted data/status transfers. One LUN-zero command is outstanding, with a 4096-byte data cap. Command tags, IU lengths, status, sense bounds, transfer completion and residue are checked. Unit Attention has a bounded retry. READ CAPACITY and READ(10/16) expose actual 512/4096-byte geometry. Queue-wrap tests read real sectors, not zero-initialized placeholders.

Each UAS device owns eight pages, one more than BOT. Stream tables and the reserved abort-status ring occupy nonoverlapping regions of the existing protocol page. A two-second native I/O deadline uses interruptible HLT. On a submitted command timeout, the driver stops old data/status transfers before sending ABORT TASK, validates the response, stops the remaining endpoints and quarantines the device. Pages remain retained until successful Disable Slot. Failure to acknowledge cancellation does not authorize freeing DMA memory.

Named high-speed and SuperSpeed tests inject EIO and a delayed backend read, require actual task-abort/endpoint-stop telemetry for deadlines, replace the device while the old backend remains throttled, and verify unchanged backing files, exact reclamation, functional input and idle CPUs. The delayed fixture is 128 bytes/second, deliberately slower than the native deadline; it does not prove behavior for every permanently nonresponsive or electrically faulty controller. Earlier emulator spin/assertion observations remain under development evidence. Correct cancellation stops old USB transfers before canceling their SCSI task.

## Remaining boundaries

No EHCI/OHCI/UHCI, SuperSpeed hub, arbitrary composite/class driver, UAS write, multiple LUN, physical hot-unplug-under-DMA or physical transaction-translator qualification is claimed. An unsupported device is reported, not treated as successfully initialized. Dedicated rejected-root and rejected-hub tests ensure a freed context never starts an input ring and a failed enumeration cannot trigger an endless retry loop. Rejected ports are retried only after a connection-status change. A healthy keyboard and idle CPUs must still work. The compacted pre-fix retry-storm observation is retained with its original log hash and repeated-line count. Factory trust, physical firmware/media and production owner-key policy remain separate follow-up work outside M45-VM-v1; installation remains M5.
